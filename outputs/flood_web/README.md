# การเชื่อม Google Sheets (ปัจจุบัน)

ฐานข้อมูล: https://docs.google.com/spreadsheets/d/1RQDU83exQhNpVYjp9JyD5UdocA6JB6GpJeXA-Qe8Pr4/edit

`server.py` อ่าน CSV จาก Google Sheets โดยตรงทั้ง 5 ชีตทุกครั้งที่เรียก `/api/data` ไม่มี cache ฝั่งแอปหรือการย้อนใช้ Excel เมื่ออ่านไม่ได้ วันที่และค่าตัวเลขถูกแปลงให้ใช้กับ Dashboard เดิมได้ หากสิทธิ์การแชร์เปลี่ยนจนเซิร์ฟเวอร์อ่านไม่ได้ จะแสดงข้อผิดพลาด ไม่เปลี่ยนสิทธิ์เอง ไม่ต้องดาวน์โหลด Excel มาวางในเครื่องอีก

เปิดด้วย `start-server.ps1` แล้วเข้า http://127.0.0.1:8765/ หรือใช้ลิงก์ Tunnel ที่กำลังทำงาน หลังแก้ไขชีตให้รอ Google Sheets บันทึกสำเร็จ แล้วรีเฟรชหน้าเว็บ การเชื่อมต่อครั้งนี้ยังใช้ Python เป็นเซิร์ฟเวอร์ ไม่ได้ deploy Apps Script

# Dashboard เฝ้าระวังน้ำ กรมอนามัย — HTML mockup

เปิดด้วย `start-server.ps1` แล้วเข้า http://127.0.0.1:8765/ ไม่เปิด HTML โดยตรง

หน้าเว็บเรียก `/api/data` ซึ่งอ่าน Excel ต้นทาง `ปภ/รายงานสถานการณ์สาธารณภัยรายจังหวัด.xlsx` ใหม่ทุกครั้งที่เปิดหรือรีเฟรชหน้า โดยไม่ฝังข้อมูลใน HTML และไม่ใช้ snapshot JSON เก่า บันทึก Excel ก่อนรีเฟรช หากอ่านไม่ได้จะแสดงข้อผิดพลาด

อ่านชีต Disaster_DB, Vulnerable_group, thai_water_DB, BKK_water_DB และ shelter_DB วันที่และยอดคำนวณจากข้อมูลที่อ่านจริง เวลานำเข้าและเวลาตรวจวัดยังอ้างอิงค่าที่บันทึกใน Excel แผนที่พื้นหลังใช้อินเทอร์เน็ต ยังไม่เชื่อม Google Sheets

ตัวเลขในข้อค้นพบเดิมด้านล่างเป็นประวัติการวิเคราะห์ ไม่ใช่ค่ากำหนดของระบบ

## หน้าจอ

- ภาพรวมประเทศ: วันรายงาน เขตสุขภาพ จังหวัด ครัวเรือน แนวโน้มน้ำ สถานีระดับน้ำ กลุ่มเปราะบาง รายละเอียดจังหวัด และ CSV
- กรุงเทพมหานคร: ครัวเรือนทั้ง กทม. สถานีคลอง 272 แห่ง ตัวกรอง 50 เขต ศูนย์พักพิง รายละเอียดผู้พัก/ที่ว่าง สถานีและพิกัดศูนย์ที่มีจริง
- ปุ่มนิยามและแผนพัฒนา: นิยามตัวชี้วัด ข้อจำกัด และขั้นตอนย้ายไป Apps Script

## แผนข้อมูลและระบบจริง

1. ยืนยันรอบรายงาน นิยามผู้ประสบภัย วันอ้างอิงประชากร และเกณฑ์ความสดกับเจ้าของข้อมูล ตรวจสถานีเวลาอนาคตและศูนย์พักเกินความจุ
2. เพิ่ม `Province_Master` และ `District_Master` พร้อมรหัสมาตรฐานและเขตสุขภาพ; แยก province/district เพราะ `district_or_area` ในสองชุดน้ำมีความหมายต่างกัน
3. เก็บ Google Sheets เป็นตาราง: รายงานภัย (วัน+จังหวัด+ประเภท), ประชากร (จังหวัด+วันอ้างอิง), สถานี (แหล่ง+รหัสสถานี), ค่าวัด (สถานี+เวลาวัด), ศูนย์พักพิง (รหัสศูนย์), สถานะศูนย์ (รหัสศูนย์+เวลารายงาน), Source_Log (รอบนำเข้า+สถานะ)
4. เก็บค่าดิบ เครื่องหมาย `-` และข้อมูลที่หายแยกจากตัวเลขศูนย์; ตรวจ key ซ้ำก่อนรวม; เวลาใช้ ISO พร้อมเขตเวลา; ไม่เขียนทับประวัติ
5. ย้ายหน้าจอไป Apps Script HTML Service; ใช้ `google.script.run` อ่านข้อมูลที่คำนวณเป็นชุดและ CacheService; Trigger ดึงข้อมูลแต่ละแหล่งตามรอบที่ตกลง; ดึงล้มเหลวแสดงสถานะเก่า ไม่สร้างข้อมูลใหม่ปลอม
6. เพิ่มข้อมูลภารกิจกรมอนามัย: น้ำอุปโภคบริโภค สุขาภิบาลศูนย์พักพิง กลุ่มเปราะบางที่ยืนยันได้รับผลกระทบ และการสนับสนุนพร้อมผู้รับผิดชอบ
7. กำหนดสิทธิ์ดู/แก้ ทดสอบการใช้งานในทีม แล้วจึงกำหนดช่องทางและผู้รับการแจ้งเตือน ปัจจุบันแสดงรายการติดตามในหน้าเว็บเท่านั้น

เกณฑ์ตรวจรับ: ยอดหน้า กทม. ตรงกับจังหวัด กทม. ในภาพรวม; เปลี่ยนวันไม่สะสมซ้ำ; ไม่มีข้อมูลไม่เท่ากับไม่มีภัย; ข้อมูลเก่าไม่เป็นสัญญาณสด; เขตไม่มีข้อมูลศูนย์ต้องไม่แสดงผู้พักเป็นศูนย์; แผนที่พิกัดหายไม่วางหมุดสมมติ
